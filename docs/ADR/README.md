# Architecture Decision Records

Store consequential architecture decisions here. Use sequential IDs such as `0001-language-strategy.md`.

Each ADR should include:
- Status: proposed, accepted, superseded, or rejected.
- Context and constraints.
- Decision.
- Alternatives considered.
- Consequences and trade-offs.
- Evidence or benchmarks.
- Date and decision owner.

Do not create ADRs to document trivial implementation details.
